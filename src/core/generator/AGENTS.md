## Purpose
The "press Generate" feature. Each `Category` has a recipe that describes the *space* of that sound: which modules to use, and value ranges that keep it recognisably acid, zap, etc. `Generator` runs recipes deterministically from a seed, respects locked parameters, and records the ranges so **Mutate** nudges values without leaving the category.

## For AI Agents

### Working In This Directory
- **Determinism is a feature.** The same category + seed + locks must give the same patch (users type seeds back in). Use only the builder's `rng` (`chance`, `rnd`, `uni`, `pick`). No `std::random_device`, time or static state.
- **Seeds are the same on every platform:** the generator sources compile with `-ffp-contract=off` (Clang/GCC; arm64 clang would otherwise fuse `a + b * c`, MSVC x64 does not). A new generator `.cpp` goes into that list in `CMakeLists.txt`.
- **Locks must not shift the RNG stream.** Locking one param must not reshuffle the others (tested). Draw first, test after: `const bool roll = b.chance (p); if (state && roll)`, never `state && b.chance (p)`, when `state` can come from a lock. The builder still consumes randomness for locked params. Keep that when adding builder methods.
- Always write params through `RecipeBuilder` (`set`/`uni`/`pick`/`among`). Writing `state()` directly skips locks and range recording, so Mutate won't touch that param.
- **Macros.** Keep `b.macros({...})` the last call of a recipe: it draws one number per macro it fills, and anything after it would shift with the patch. List the targets that make sense for the category, most useful first. Kick recipes have no macros (the kick engine ignores the matrix).
- **Energy.** `generate()` keeps the current `EnergyMode` (the user's unit, like Quality) and mutate never touches it. Recipes set both `EnergyBars` and `EnergySec`. Let the sweep shape the gesture (amp env with a short attack and sustain 1, `EnergyFade` for the level) so the Length control stretches everything.
- `uni` samples in the parameter's normalised curve (log for Hz, power for times). Give ranges in plain units.
- **User settings Generate keeps:** `Quality`, `RenderQuality`, `MasterVol`, `EnergyMode`, `ArpKey`, `ArpScale` are copied from the current patch and skipped by Mutate. `FxOrder` is not: a new patch starts in the default chain.
- **Kicks.** `generate()` sets `EngineMode` from the category after the recipes, ignoring locks, and `mutate` never touches it. `generate(..., kickToKey)` sets `KickKeyTrack` for kick categories without drawing randomness, so a seed gives the same kick with the toggle on or off. A new kick needs a `familyOf` case, a recipe in `KickRecipes.cpp` and cases in `recipeFor()`, `arpRecipeFor()` and `arpPatternRecipeFor()` (the arp ones return `noArp`).
- **Basses.** Psy Bass (enum `PsyBass`, index 4, formerly Rolling Bass), Bass Shot, Offbeat Bass and Prog Bass (`Family::Bass`; Ghost Bass and Jilax Bass too) play the synth engine but, like kicks, never get an arp: `generate()` drops `withArp` for families without `hasArp`, and the processor forces `ArpOn` off for them on every state it applies. Their recipes (`Recipes.cpp`) were fitted to reference samples: harmonics h2-h8 in windows over the note, pitch knock (`bassKnock`), envelope, crest, level. They end in `fxCompBass`, a glue comp whose make-up puts them level with the kicks. Reverse Bass and Reverse Sub (appended, indices 32-33) are one-shots played backwards: `hasLength()` is true for them, so they get the Length panel and stop at `EnergyBars` (1/4 bar by default, `reverseLength`) with Cut at End; Reverse Bass was fitted to the twelve bright reverse shots in `~/Downloads/Bass Shots 2` (017 E, 024, 043, 049-051, 055, 062, 072, 074, 079, 080): always a saw, the phaser as a static all-pass (80 %), Hiss noise (type 3, Direct, 0.12-0.28: 017 E's fizz over the spike), `AenvStart` 0.025-0.35, attack 26-66 % of one beat; per patch an LP6 wide open or a darker LP12, the 500 Hz parallel notch (60 %), an octave saw on Osc B (30 %), extra tube/hard drive (30 %), a fall onto the note (Sweep → PitchAll with `EnergyDelay`, 20 %) or the filter opening through the swell (Sweep → F1 Cutoff, 35 %), Width with a mono low end (45 %); the swell comes from `AenvCurve` (and `AenvStart`), the sub's slide from `ModSrc::Sweep` → `PitchAll`, held by `EnergyDelay` 0.55-0.63 and then straight (falls, `EnergyCurve` -0.5..-0.15) or easing in (rises). Reverse Sub was fitted to 018 E, 025 G#, 026 G#: falls start an octave up as a warm sine (Osc B sine an octave up at 0.08-0.2 for h2, tube 19-24 dB for h3), the rise is a saw through BP24 with full key tracking (h2 above h1); attack 53-60 % of the beat, `AenvCurve` 0.62-0.78; always one beat. They end in `fxGainBass` (make-up only, the threshold above the swell) instead of `fxCompBass`. Amp attacks start at `kBassAttackLo` (1.5 ms): an instant attack clicks at every note start and on retriggers out of a release tail.
- **Ghost Stab / Ghost Bass.** Recalibrating: the reference measurements and renders are scratch work (stems from demucs `htdemucs_ft`, beat grid from the drums stem, main sections where kick and bass are loud); the stab is measured beat-folded with the first half of the beat subtracted as background, the bass per note. The references' valleys between harmonics (30 dB) and their first-half-of-beat energy are filled by the rest of the mix in the stem, so don't fit those.
